# じぶんの ろせんず

駅名を聞き、ひらがなを一文字ずつ書き、自分の路線図を育てるiPad向けWebアプリです。なぞりと自由書きには寛容な補助判定があり、判定結果にかかわらず子ども自身の「できた」を記録できます。

東急電鉄の9路線・公式99駅相当、相模鉄道（相鉄）の3路線・27駅、東京メトロの9路線・180駅を全区間収録しています。同じ実在駅は会社や路線をまたいでも一つのStation IDへ統合しているため、組み込みStationレコードは264件です。路線図は駅順を表す独自の模式図で、地理的な距離を表す地図ではありません。

収録路線は次の21路線です。

- 東急電鉄: 東横線、目黒線、東急新横浜線、田園都市線、大井町線、池上線、東急多摩川線、世田谷線、こどもの国線
- 相模鉄道: 相鉄本線、相鉄いずみ野線、相鉄新横浜線
- 東京メトロ: 銀座線、丸ノ内線、日比谷線、東西線、千代田線、有楽町線、半蔵門線、南北線、副都心線

東京メトロは東急9路線と相鉄3路線を通常クリアすると解除され、最初は銀座線と半蔵門線から始まります。各路線で練習した文字位置が25・50・75・100%へ達するたびに区間スタンプを獲得し、最初は2個、その後は3個ごとに好きなメトロ路線を1本選んで開けます。みなとみらい線、JR線、都営地下鉄など各社の直通先は含みません。

## 主な機能

- 鉄道会社→路線の順で選び、全駅を見たり聞いたりできる簡略SVG路線図
- 固定マイルストーンによる会社・路線・将来モード共通の解除基盤と、解除までの残り路線表示
- 駅名の長さを含む練習文字数で公平に算出する25%ごとの区間スタンプと、好きなメトロ路線を選べる路線きっぷ
- 文字ラベルとMaterial Symbolsを組み合わせた、子どもにも意味が伝わる操作ボタン
- 長い駅名に合わせた駅間隔の自動調整と、長い路線の横スクロール
- 基本46文字、濁音・半濁音、小さい文字から駅を探せ、練習済みの文字も分かるひらがな索引
- 一致文字の強調、共有駅の複数路線表示、該当位置からの直接練習
- 一文字の音声、駅名全体の音声、指で文字列をなぞる読み上げ
- 画順・始点・番号つきのなぞり書きと自由書き
- 「やさしい・ふつう・しっかり」の3段階で、始点・許容範囲・通過率・画順を確認するなぞり補助判定
- お手本なしの自由書きを位置・大きさ・縦横比を補正し、字形だけで緩く確認する上位クリア
- 一文字から駅を追加し、隣接駅を電車でつなぐ演出
- 文字位置ごとの途中保存、路線別の完了駅数、通常クリア（★）とお手本なしクリア（★★）の印
- 路線全駅クリア時の全線点灯・電車走行・記念カードと、いつでも再生できる路線メダル
- 全駅をお手本なしで書いた路線の上位称号「ろせんマスター」
- 「わたしの きろく」で全体進捗、近い目標、会社別アコーディオン式スタンプ帳、路線メダル、練習済みひらがな、達成日つき履歴を確認
- 左利き・右利き、音声、動きを減らす設定
- 全訪問で読み込むGoogle Tag Manager経由のアクセス解析
- カスタム駅の追加・編集と既存路線への手動挿入
- 全国追加に備えた会社別データセットと、重複・参照漏れを検出する固有IDカタログ
- 検証つきJSONバックアップ・置換復元
- ホーム画面からアプリ表示で起動できるPWA・オフライン再起動

位置情報、地図タイル、Googleマップ連携、ログイン、クラウド同期、AI/OCR採点は初版に含みません。将来の地図連動では駅データに座標または外部地図参照を追加し、現在の模式図データとは分けて扱います。

## 必要環境

- Node.js 22.13以上（CIはNode.js 24）
- npm 11系
- 開発確認: 現行のSafari、Chrome、Firefox
- 主対象: iPad Safari、CSSビューポート 1024×768 / 768×1024相当

## 開発

```bash
npm ci
npm run dev
```

表示されたローカルURLをブラウザで開きます。

```bash
npm run typecheck
npm test
npm run build
npm run preview
```

`npm run build`は型検査とテストも実行し、`dist/`へ静的ファイルを生成します。プロジェクトサイト相当のパスをローカルで確認する場合は次のようにします。

```bash
BASE_PATH=/repository-name/ npm run build
```

## GitHub Pagesで公開する

1. このコミットを、公開先として用意したGitHubリポジトリの`main`ブランチへpushします。
2. GitHubで **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にします。
3. **Actions** の `Test, build, and deploy Pages` が成功するのを待ちます。
4. workflowの`deploy`結果、または **Settings → Pages** に表示されるURLをiPad Safariで開きます。

workflowはPages設定から`base_path`を取得するため、`/<repository>/`配下でも、ユーザーサイトやカスタムドメインの`/`配下でもアセットを読み込めます。画面URLにはハッシュ方式を使い、駅画面で更新してもPagesの404になりません。

検索エンジン向けのサイトマップは`public/sitemap.xml`、案内は`public/robots.txt`にあります。現在の画面遷移はハッシュ方式のため、サイトマップへ登録する正規URLはトップページだけです。将来ハッシュを使わない公開画面を追加した場合は、そのURLと更新日をサイトマップへ追記します。

### Google Search Console / Tag Manager / Analytics

- Search ConsoleのURLプレフィックスは `https://microgravity.github.io/routemap-kana/` です。`index.html`にHTMLタグ方式の所有権確認タグを収録し、2026-09-09に所有権確認済みです。`https://microgravity.github.io/routemap-kana/sitemap.xml`を送信します。
- GTMコンテナは `GTM-MXG5B2NT` です。Google Analyticsの測定ID `G-CVGD2ZHNYD` はGTM側のGoogleタグへ設定し、コンテナを公開します。GAをサイトへ直接重複設置しません。
- GTMは保護者同意の設定を介さず、すべての訪問で読み込みます。計測可否や同意モードが必要になった場合は、GTM側の設定またはサイトのプライバシー設計を合わせて見直します。
- ハッシュ形式の画面遷移は、GA4の拡張計測にあるブラウザ履歴に基づくページ変更を有効にして計測します。GTM側で別の履歴変更タグも追加する場合は、`page_view`の二重計測にならないよう片方だけを使用します。

GTMのプレビューまたはTag Assistantで、最初の表示時にGoogleタグが一度だけ発火すること、画面移動時に`page_view`が一件ずつ届くことを確認します。

更新時は`main`へpushすると、型検査、重要テスト、本番ビルド、Pages公開が順に実行されます。公開先リポジトリとURLはこのソース内に決め打ちしていません。

## iPadで使う

Safariで公開URLを開き、共有ボタンから「ホーム画面に追加」を選択します。追加したアイコンから開くと、アドレスバーのないスタンドアローン表示で起動します。初回はオンラインで全画面を一度開いてから、オフライン起動を確認してください。アプリ本体とひらがなのお手本は端末へキャッシュされます。音声は端末の日本語音声とSafariの動作に依存し、最初の読み上げは必ず利用者のタップから開始します。

公開版を更新するとService Workerが新しい版を検出し、次回の制御切替時に一度だけ再読み込みします。更新が見えない場合はオンライン状態でアプリを終了して開き直してください。それでも変わらない場合はホーム画面のアイコンを削除して、Safariから追加し直します。

手書き面では指・Apple Pencilの操作を描画専用にし、ページスクロール、ラバーバンド、長押しメニューを抑止します。手書き面の外では通常どおりスクロールできます。

保存先はブラウザ内の`localStorage`です。ブラウザデータの削除などで失われる場合があり、Safari表示とホーム画面表示の間や別端末へ自動同期される保証はありません。「おうちのひと」画面から定期的にJSONを書き出してください。

筆跡そのものは永続保存しません。「できた」にした文字位置、お手本なしで書けた文字位置、次回の再開位置、駅追加状態を区切りごとに保存します。従来の保存データには、お手本なし進捗を空の状態で補い、そのまま読み込めます。

解除済みマイルストーン、区間スタンプ、選んだ路線も保存・バックアップします。解除記録がない従来データはそのまま読み込み、条件をすでに満たしていれば起動時に自動解除します。段階解除導入前に東京メトロを解除済みだったデータでは、利用できていた9路線を再ロックしません。将来のカタカナ・漢字モードに備えてモードIDと解除参照を分離していますが、現在提供する練習モードはひらがなです。

プロフィール用の集計値は保存せず、現在の駅データ、`practicedPositions`、`freeWrittenPositions`、`unlockedMilestones`から毎回算出します。共有駅は全体の駅数では一度だけ数え、所属する各路線の進捗にはそれぞれ反映します。プロフィールは`#/profile`のハッシュ画面なので、サイトマップへ別URLとしては追加しません。

区間スタンプ、路線クリア、路線マスターの初回達成日時は`milestoneHistory`へ保存します。機能追加前からクリア済みの路線は、各駅に残る最初の保存日時から日単位の過去履歴を復元します。過去の区間スタンプは正確な取得日時が残っていないため遡って生成しません。
