# データ追加ガイド

## 親画面から駅を追加する

1. 子ども画面右上の「おうちのひと」を約1秒長押しします。キーボードではボタンへフォーカスしてEnterを押せます。
2. 「駅を追加・編集」で「あたらしい駅」を選びます。
3. 駅名、ひらがなの読み、必要なら音声用の読みを入力します。
4. 「みつけた えき」に置くか、既存路線と挿入位置を指定します。
5. お手本対応状況と音声を確認して保存します。

未対応文字があっても駅は追加できます。その文字はフォントのお手本と自由書きになり、画順アニメーションは表示しません。既存路線への挿入は指定された駅の直後に入り、地理的な位置を自動推測しません。

## 組み込み駅・路線を変更する

組み込み駅・路線は東急、相鉄、東京メトロの会社別ファイルに分け、[`src/data/stations.ts`](../src/data/stations.ts)で統合します。全国追加時の分割単位、固有ID、共有駅の規則は[`railway-data-architecture.md`](railway-data-architecture.md)を参照してください。

- `Station.id`は駅名や配列位置から作らず、公開後は変更しません。新規会社は`nationwideRailwayId`で全国版IDを生成します。
- 読みはUnicode NFCのひらがなにします。
- 同じ実在駅を複数路線で使う場合は同じ駅IDを共有します。
- `Route.orderedStationIds`が隣接関係と電車演出の根拠です。
- `Route.stationCodes`は`orderedStationIds`と同じ順・同じ件数にします。
- `segmentLabel`に収録区間を明示します。
- 公式情報を確認し、[`docs/sources-and-licenses.md`](sources-and-licenses.md)へ出典を追加します。
- 公開後の解除条件は「現在の全路線」から動的に作らず、`src/domain/unlocks.ts`へ固定ID・固定路線集合のマイルストーンとして追加します。
- 長い路線の途中実績は駅数ではなく、各駅の読みで練習済みになった文字位置の割合から算出します。現在は25・50・75・100%を区間スタンプとしています。
- 選択式の解除は獲得スタンプ数から使える路線きっぷを算出し、選んだ路線の固定解除IDだけを保存します。新路線追加時に既存の解除数や必要数が変わらないよう、必要スタンプ数と対象路線IDを版付きで固定してください。

追加後は必ず次を実行します。

```bash
npm run typecheck
npm test
npm run build
```

画順カバレッジテストが不足文字を列挙します。現在、長音符「ー」と小さい「っ」はライセンス済み画順データに含まれないため、フォント見本と自由書きで扱います。

ひらがな索引はStationデータから実行時に計算します。文字ごとの駅リストを別ファイルへ手書きしないでください。追加・編集・削除したカスタム駅と組み込み駅の上書きも同じ索引へ自動反映されます。

## 画順SVGを追加する

画順データは [`src/data/kana/glyphs`](../src/data/kana/glyphs) に、一文字一ファイル、`0 0 1024 1024`のviewBoxで保存します。ファイル名はNFC正規化した一文字です。

通常のフォント輪郭から中心線を自動生成したものを、正しいお手本として追加しないでください。新しい出典を使う場合は、再配布・改変条件と教育用の字形・画順を確認し、ライセンス全文または必要な通知を`licenses/`へ保存します。

## 保存形式

JSONには`schemaVersion`があります。既存フィールドの意味を変えず、互換性のない変更時はバージョンを上げ、`src/services/storage`へ明示的な移行処理とテストを追加します。インポートは全件検証後の置換方式を維持してください。

`unlockedMilestones`は一度獲得したコンテンツ解除、区間スタンプ、選択した路線を保持するための記録です。路線進捗そのものは従来どおり`progress`から算出し、重複保存しません。`unlockSystemVersion`は解除方式の移行に使用し、旧版ですでに利用できたコンテンツを再ロックしないようにします。将来の練習モードは`LearningModeId`で区別し、駅IDだけをキーとする現在のひらがな進捗へカタカナ・漢字の位置を混在させないでください。

「わたしの きろく」の集計も同じ原則で、プロフィール専用の合計値を保存しません。共有駅を全体で重複計上せず、路線別には各所属路線へ反映し、カスタム駅も現在の挿入先から集計します。新しい実績表示を追加する場合は、既存の進捗と固定マイルストーンから導出できるかを先に確認してください。

`milestoneHistory`だけは「いつ達成したか」を後から算出できないため、区間スタンプ・路線クリア・路線マスターの初回日時をイベントとして保存します。同じイベントIDは一度だけ記録します。導入前の路線クリアは各駅の`addedAt`のうち最も新しい日付から復元し、正確な日時を復元できない過去スタンプは追加しません。

## サイトマップ

検索エンジン向けの正規URLは`public/sitemap.xml`で管理します。`HashRouter`の`#/kana`や`#/station/...`はフラグメントであり、検索エンジン上の別URLにはならないため追記しません。将来、ハッシュを使わない固定の公開画面を追加した場合は、完全なHTTPS URLを`<url>`として追加し、該当する`<lastmod>`も更新してください。`public/robots.txt`のサイトマップURLも、公開ドメインやベースパスを変更した場合に合わせて更新します。

## 検索確認とアクセス解析

Search ConsoleのHTML確認タグは`index.html`で管理します。削除や値の変更をすると再確認に失敗する場合があるため、公開URLや所有者を変更するとき以外は維持してください。

GTMコンテナは`index.html`から全訪問で読み込みます。計測項目を増やす場合も、筆跡、追加駅の表示名、バックアップ内容、文字位置ごとの進捗など、子どもの入力・学習内容をイベント値に含めないでください。GAタグはGTM側だけで管理し、サイト側との二重計測を避けます。
